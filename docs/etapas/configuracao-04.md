# Configuração de publicação da 04

1. Vercel, projeto `escritoriojn`, time `escritorio-jn`: configurar `VITE_SUPABASE_URL` como URL do projeto novo e `VITE_SUPABASE_PUBLISHABLE_KEY` como sua chave publicável em Production/Preview (conforme destino aprovado). São configurações públicas, iguais no browser/API. Não usar secret/service_role. Build Vite precisa delas antes da compilação; gerar novo deployment após ajuste.
2. Supabase Auth>URL Configuration: Site URL `https://escritoriojn.vercel.app`. Permitir `https://escritoriojn.vercel.app/auth/callback` e `https://escritoriojn.vercel.app/auth/callback?**` para parâmetros de PKCE/área. Acrescentar o callback do preview específico se ele for usado para homologação. Evitar wildcard no domínio de produção. O aplicativo ignora destinos externos/next e só navega por rotas internas fixas.
3. Manter confirmação de e-mail habilitada e SMTP customizado já configurado. Senha de aplicativo permanece somente no Supabase; templates ficam para etapa futura. Não exigir TOTP/QR/MFA. Considerar o advisor de senhas vazadas conforme elegibilidade do plano, sem contratação automática.
4. Com conta fictícia autorizada no ambiente: cadastrar cliente, abrir confirmação no mesmo navegador, entrar/sair e tentar painel depois de sair; recuperar senha no mesmo navegador, verificar destino, alterar senha e rejeitar link antigo. Não postar senha/token no chat. Conta sem vínculo deve ser negada mesmo autenticada.
5. Registrar deployment/CI e resultado real de entrega externa, sem incluir endereços pessoais ou tokens no repositório. Etapa 05 aguarda o aceite da 04.
